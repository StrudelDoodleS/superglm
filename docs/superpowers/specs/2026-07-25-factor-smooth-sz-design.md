# Unified FactorSmooth `fs` / `sz` Design

**Date:** 2026-07-25
**Status:** Approved conversational design; written-spec review pending

## Summary

Extend the existing `FactorSmooth` feature into one public API for two
factor-by-smooth geometries:

```python
FactorSmooth("age", group="region", basis="fs", kind="ps", k=6, m=2)
FactorSmooth("age", group="region", basis="sz", kind="ps", k=6, m=2)
```

`basis` chooses the factor interaction geometry. `kind` chooses the marginal
smooth basis. The initial marginal implementation remains `kind="ps"`.

- `basis="fs"` preserves the existing fully penalized, all-level factor
  smooth and remains the default.
- `basis="sz"` adds an exact sum-to-zero deviation smooth around a required
  global `Spline` main effect.

The SZ implementation uses compact exact/discrete matrix kernels and a
structured equality-constrained solver. It must not expand an `n x Kk` design
or a `Kk x Kk` Hessian during the structured fit.

This work does not change LSS code or semantics.

## Goals

1. Preserve all current `RandomEffect` and `FactorSmooth(..., basis="fs")`
   behavior, prediction, reporting, mgcv parity, and structured performance.
2. Add mgcv-style `bs="sz"` smooth deviations with coefficientwise
   sum-to-zero constraints.
3. Keep one discoverable public API while separating factor geometry from
   marginal spline kind.
4. Make invalid main-effect combinations fail early with corrective messages.
5. Support exact and `discrete=True` REML fits with compact kernels.
6. Match dense reference algebra and pinned mgcv 1.9-4 results.
7. Profile the real call stack and document the performance crossover.

## Non-goals

- Adding `te`, `tp`, or another tensor-product constructor.
- Renaming or redesigning the existing tuple interaction dispatcher.
- Adding a new `SplineInteraction` class.
- Supporting non-P-spline marginals in this release.
- Supporting per-level SZ smoothing parameters in this release.
- Adding correlated random slopes or a general hierarchical random-effects
  syntax.
- Changing selection-penalty or LSS fitting behavior.

## Evidence Hierarchy and Clean-Room Boundary

mgcv is the behavioral and statistical reference for this feature. The
priority order is:

1. mgcv's published documentation and Simon Wood's published numerical work;
2. outputs generated by executing a pinned mgcv release;
3. clean-room observations of externally visible mgcv behavior and known
   historical pitfalls;
4. permissively licensed libraries as secondary implementation context only.

The reference environment used while writing this design is R 4.5.3 with
mgcv 1.9-4. The audited CRAN mirror revision is
`1b6a4c8374612da27e36420b4459e93acb183f2d` (version 1.9-4).

mgcv is GPL. No mgcv source text, comments, private identifiers, control flow,
or code structure may be copied into SuperGLM. Implementation must be derived
from the equations and behavior written in this specification and expressed
using SuperGLM's existing abstractions. Reference fixtures are produced by
running mgcv and record the R version, package version, formula, seed, data,
and outputs; they do not embed upstream implementation code.

A targeted permissive-license survey found no MIT-licensed library implementing
all three of RE, FS, and SZ. Apache-2.0 `hypercoil/nitrix` contains random-effect
and grouped smooth concepts but no mgcv-compatible SZ construction; Apache-2.0
pyGAM and BSD-3-Clause statsmodels likewise do not supply this exact trio.
These libraries do not override mgcv behavior, and no third-party code needs
to be adapted for this implementation.

## Terminology and mgcv Mapping

`group="region"` identifies the categorical grouping factor. It is not a
generic spelling of mgcv's `by=` argument.

| SuperGLM | Closest mgcv form | Meaning |
|---|---|---|
| `FactorSmooth("x", group="g", basis="fs")` | `s(x, g, bs="fs", xt=list(bs="ps"))` | Fully penalized curve per level |
| `FactorSmooth("x", group="g", basis="sz")` | `s(x, g, bs="sz", id=1, xt=list(bs="ps"))` | Curves sum to zero at every `x` |
| Existing `SplineCategorical` | Factor `by=` smooth | Reference-coded spline/categorical interaction |
| Existing two-spline tuple interaction | `ti()`-style interaction | Main-effect-compatible tensor interaction |

An mgcv `by=` variable multiplies a smooth basis and has broader numeric and
factor semantics. SuperGLM's `group=` instead controls fitted levels,
factor contrasts, shrinkage geometry, compact kernels, and unseen-level
prediction.

## Public API

The constructor becomes:

```python
FactorSmooth(
    variable: str,
    *,
    group: str,
    basis: Literal["fs", "sz"] = "fs",
    kind: str = "ps",
    k: int = 6,
    m: int = 2,
    unseen: Literal["population", "error"] = "population",
    missing: Literal["error"] = "error",
    lambda_policy: LambdaPolicy | dict[str, LambdaPolicy] | None = None,
    name: str | None = None,
)
```

Default names are:

- `f"{variable}:{group}:fs"` for `basis="fs"`
- `f"{variable}:{group}:sz"` for `basis="sz"`

Existing calls omit `basis`, retain the same name, and follow the unchanged FS
path.

No `shared=` argument is exposed yet. The first SZ implementation has one
shared wiggle smoothing parameter across levels, equivalent to mgcv's
`id=1` construction. A future per-level implementation can add an explicit
option when both modes exist.

### Lambda policy

- FS keeps its current `wiggle`, `null_0`, ..., `null_{m-1}` components.
- SZ has only a `wiggle` component. Its marginal null space is intentionally
  unpenalized.
- A scalar `LambdaPolicy` applies to every component available for the chosen
  basis.
- A mapping may mention only component names available for that basis.

### Canonical model spelling

The required global spline for SZ is configured explicitly:

```python
SuperGLM(
    features={"age": Spline(kind="ps", k=6, m=2)},
    interactions=[
        FactorSmooth("age", group="region", basis="sz", kind="ps", k=6, m=2)
    ],
)
```

`Spline` and `FactorSmooth` have independent marginal configurations. They
may deliberately use different `k` values, but documentation uses matching
`kind` and `m` unless explaining the consequences of a different choice.

### Legacy auto-detection shorthand

Passing `splines` as anything other than `None`, including `splines=[]`,
activates a legacy auto-detection shorthand family. It remains functional
during the compatibility window but emits one `FutureWarning` per
`SuperGLM` construction with `stacklevel=2` and an explicit migration example
using `features={name: Spline(...)}`.

The companion `n_knots`, `degree`, and `categorical_base` arguments remain
available for compatibility with that deprecated mode. New documentation,
examples, validation messages, and FS/SZ tests use explicit `features`.
No removal version is promised by this design.

## Model Compatibility Rules

Validation occurs after feature and interaction resolution, so legacy
auto-detection cannot bypass the same rules applied to explicit feature maps.

1. `basis="fs"` may be fitted alone.
2. FS may coexist with a global `Spline` on the same numeric variable.
3. `basis="sz"` requires a global spline feature on the same numeric variable.
   A `Numeric` main effect is not sufficient.
4. A `Categorical` main effect on the grouping column is rejected for either
   basis because it duplicates the group-intercept direction.
5. A `RandomEffect` on the grouping column is rejected for either basis
   because it duplicates the same constant-by-group geometry.
6. Only one `FactorSmooth` may use a given `(variable, group)` pair, regardless
   of custom name or whether the requested basis is FS or SZ.
7. `variable` and `group` must remain distinct.
8. SZ requires at least two observed fitted group levels.

Errors name both conflicting terms and show a valid replacement. The SZ
missing-main-effect error shows the explicit
`features={variable: Spline(...)}` form.

The deprecated auto-detection path resolves its inferred feature specs before
this validation. If it infers a `Categorical(group)` that conflicts with FS or
SZ, the fit fails with the same duplicate-geometry error and an explicit
feature-map migration example. The new interaction API does not add another
special case to legacy inference.

### Why the rules differ

FS is fully penalized. Its global-versus-level decomposition is determined by
penalties and can be useful as a standalone random curve. SZ is an interaction
deviation with an exact zero-sum constraint, so the global spline carries the
population curve. A categorical or random-intercept group main effect repeats
a direction already present in the factor-smooth marginal null space.

## Statistical Geometry

Let:

- `K` be the number of fitted group levels;
- `k` be the marginal basis width;
- `B(x)` be the shared `1 x k` P-spline basis row;
- `S` be its order-`m` difference penalty;
- `rank(S) = k - m`.

### FS

FS retains `Kk` coefficients, one independent `k`-vector per level. The
existing natural parameterization and repeated wiggle/null penalties are
unchanged. With `m=2`, FS continues to estimate shared `wiggle`, `null_0`, and
`null_1` smoothing parameters across all levels.

### SZ

Define the `K x (K - 1)` contrast:

```text
C = [ I_(K-1) ]
    [ -1 ... -1 ]
```

With free coefficients `beta` containing `K - 1` level-major blocks, the full
level coefficient matrix is:

```text
theta = (C kron I_k) beta
```

Therefore:

```text
sum_j theta_j = 0
sum_j B(x) theta_j = 0    for every x
```

The public coefficient width is `(K - 1)k`. The first `K - 1` sorted levels
store free blocks and the final level reconstructs as their negative sum.
This storage convention does not alter the symmetric fitted curves.

The shared SZ penalty is:

```text
Omega_sz = (C' C) kron S
         = (I + 11') kron S
```

Equivalently, in full constrained coordinates it is
`sum_j theta_j' S theta_j`. It has:

```text
rank(Omega_sz) = (K - 1)(k - m)
nullity(Omega_sz) = (K - 1)m
log|Omega_sz|+ = (K - 1) log|S|+ + (k - m) log(K)
```

The unpenalized null space is intentional and matches SZ semantics. As lambda
grows, group curves approach level-specific degree-`m - 1` polynomial
deviations rather than collapsing to zero. SZ is therefore not a credibility
shrinkage model for very sparse groups; FS is the recommended basis when full
shrinkage is required.

## Marginal Construction

The factor geometry and marginal construction are separate internal choices.

- FS continues to use its current mgcv-compatible P-spline knot placement and
  natural parameterization without numerical changes.
- SZ uses the same mgcv-compatible uncentered `k`-column P-spline marginal and
  order-`m` difference penalty, followed by the factor contrast above.
- The SZ marginal is not centered independently: the factor contrast supplies
  the identifiability constraint, and the separately fitted global `Spline`
  represents the population curve.

`kind != "ps"` remains a clear `NotImplementedError`. The API separation makes
future marginal kinds additive rather than requiring new public feature names.

## Compact Matrix Representation

`FactorSmoothGroupMatrix` remains the internal compact grouped-spline matrix.
It gains an FS/SZ geometry flag while retaining the existing FS execution
path unchanged.

Shared stored state remains:

- observation-level group codes;
- exact sparse marginal basis or discrete support basis plus bin indices;
- marginal transform and penalty;
- fitted level labels.

For SZ:

- `shape[1]` is `(K - 1)k`;
- `matvec` evaluates a local free block for the first `K - 1` levels and the
  negative sum of blocks for the final level;
- `rmatvec` accumulates raw level totals, then applies `C'`;
- dense `gram()` and `toarray()` remain small-model oracle operations only;
- structured fitting consumes raw per-level Grams, cross-products, and right
  hand sides directly.

The exact and discrete kernels share the same contrast algebra. Neither path
constructs a one-hot matrix, an expanded spline-by-level matrix, or a full
factor-smooth Hessian.

`GroupInfo` records both the raw level count and factor basis. Its coefficient
width invariant is `Kk` for FS and `(K - 1)k` for SZ.

## Structured SZ Solver

### Symmetric constrained system

The structured solver keeps all `K` level blocks internally and enforces the
sum-to-zero constraint directly. This avoids making the stored final level a
numerically privileged reference.

Let `a` collect the intercept and every eligible dense-small ordinary
coefficient. Raw per-level sufficient statistics produce:

- ordinary block `A`;
- cross block `C_j`;
- local block `D_j = B_j' W_j B_j + lambda S`;
- ordinary and per-level right hand sides.

With `H_raw` assembled conceptually from `A`, `C_j`, and block-diagonal `D_j`,
and:

```text
G = [0_q, 1_K' kron I_k]
```

the solver handles:

```text
[ H_raw  G' ] [a, theta]' = [rhs, 0]'
[ G       0 ]
```

The matrix is never assembled at full size.

### Local elimination

Positive-definite `D_j` blocks are factored independently. Eliminating them
leaves a dense symmetric bordered system of size `q + k`, where `q` is the
ordinary small-block width. It is factored with a rank-revealing symmetric
LDL decomposition, with SVD used only for numerical diagnosis/fallback.

If a local block is positive semidefinite rather than positive definite, its
range is eliminated and its orthonormal null directions are promoted into the
bordered system. If `R` total local null directions are promoted, the dense
remainder has size `q + k + R`. For a globally identifiable constrained model,
`R <= k`; otherwise the solver reports global non-identifiability. A thin
level is therefore not rejected merely because its local block is singular.

The error reports the term, deficient rank, implicated levels, and recommends
FS or more support. It is raised only when the complete constrained system is
unidentifiable.

### Determinant and public-coordinate solve

Let:

```text
T = diag(I_q, C kron I_k)
```

map public free coordinates to raw constrained coordinates. The public Hessian
is `H_free = T' H_raw T`. Since:

```text
det(T' T) = K^k
det(G G') = K^k
```

the absolute KKT determinant equals `det(H_free)`. The structured factor can
therefore provide the exact log determinant needed by REML using local
log-determinants plus the bordered log-absolute-determinant, without a hidden
constant.

For arbitrary public-coordinate solves, right hand sides are lifted with
`T(T'T)^-1`, solved through the constrained factor, and mapped back with the
left inverse of `T`. The fitted coefficient vector keeps the normal SuperGLM
layout: ordinary terms followed by `(K - 1)k` SZ coefficients.

### Complexity

For positive-definite local blocks, expected fitting cost is:

```text
time:   O(nnz(B) + K k^3 + K k^2(q + k) + (q + k)^3)
memory: O(K k^2 + K k q + (q + k)^2)
```

Promoted null directions replace `q + k` with `q + k + R`.

There is no `O((Kk)^2)` allocation on the structured path. Existing
eligibility and fallback diagnostics remain visible. A forced structured fit
must fail clearly when the dense-small remainder is ineligible rather than
silently materializing the full system.

## REML and Compact Inference

SZ contributes one compact penalty component with a new sum-to-zero geometry.
Dense reference code may materialize `(C'C) kron S` for small tests; production
structured code uses the marginal `S`, level count, and constraint.

In raw constrained coordinates, the derivative penalty is simply
`blockdiag(S, ..., S)`. This makes REML traces, cross-traces, weight
derivatives, and selected covariance compatible with the existing
block-diagonal-plus-low-rank machinery.

The new constrained factor implements the complete existing `HessianFactor`
protocol:

- solve and log determinant;
- selected inverse blocks/diagonals;
- inverse-penalty and penalty-cross traces;
- compact operator traces;
- weight-derivative diagonals and cross-traces.

It exposes level-curve covariance for every raw level, including the
reconstructed final level, without requesting the full free-coordinate
covariance matrix.

## Prediction and Reconstruction

For a known SZ level:

```text
eta = ordinary effects + global spline(x) + deviation_level(x)
```

The final fitted level uses the negative sum of free coefficient blocks.

- `unseen="population"` returns zero SZ deviation, leaving the global spline.
- `unseen="error"` raises with the unseen labels.
- `predict(..., random_effects="population")` zeroes FS/SZ deviations for all
  groups, preserving the existing public switch and the global spline.
- Exact prediction always evaluates the fitted continuous marginal basis,
  even when estimation used `discrete=True`.

`reconstruct()` returns coefficients for all `K` fitted levels and includes
the factor basis in its metadata.

## Reporting

`model.factor_smooth(name, ...)` remains the single reporting entry point.
`FactorSmoothResult` gains a `basis` field while preserving existing FS
fields and table columns.

FS reporting remains unchanged:

- component variance estimates;
- level credibility and shrinkage;
- collapse diagnostics;
- curve estimates and intervals.

SZ reporting must not claim credibility shrinkage:

- `collapsed` is `None`, because infinite wiggle smoothing does not eliminate
  the unpenalized polynomial deviations;
- the level table contains support, fit weight, information rank/trace, and
  coefficient norm, but no `credibility` or `shrinkage` columns;
- curves and posterior intervals are returned for every fitted level;
- diagnostics include the maximum absolute sum of level effects over the
  requested grid, which must be zero to numerical tolerance;
- overall effective degrees of freedom and lambda-boundary diagnostics remain
  available.

Documentation explicitly recommends FS for sparse-level credibility and SZ
for an interpretable global curve plus exactly centered deviations.

## Tabmat and Kernel Strategy

Tabmat remains in use for ordinary dense, sparse, and categorical blocks and
for the dense-small side of the structured system. The grouped spline block
continues to use specialized kernels because its natural representation is
`codes + shared basis`, not a conventional CSC/CSR matrix.

The new SZ kernels reuse the existing raw per-level moment kernels and apply
the small contrast algebra around them. Expanding into a stock tabmat
`SparseMatrix` would lose the compact representation and force expensive
generic sandwich operations. A future tabmat grouped-spline matrix type could
host the same kernels, but is not required for this feature.

## Error Handling and Fallbacks

The implementation distinguishes configuration errors from numerical errors:

- invalid `basis`, `kind`, lambda component, or one-level SZ: constructor/build
  error;
- missing global SZ spline or duplicate group geometry: model configuration
  error before optimization;
- unsupported selection fit: existing `fit_reml()` guidance;
- globally unidentifiable constrained system: numerical error with deficient
  levels and remediation;
- structured ineligibility: existing backend fallback reason in auto mode,
  explicit error in forced structured mode.

No path silently changes SZ into FS, adds a group main effect, penalizes the SZ
null space, or chooses per-level smoothing parameters.

## Upstream Pitfalls Converted to Native Tests

External bug histories are used only to identify failure classes. mgcv remains
the oracle for expected behavior, and no third-party implementation detail is
copied. The SuperGLM regression suite must cover:

- stable FS natural parameterization that keeps penalized and unpenalized
  directions orthogonal to numerical tolerance;
- no use of FS as a tensor-product margin and a clear rejection if a future
  dispatcher attempts it;
- exact replay of marginal and factor transforms at prediction time;
- one-row prediction without dimension dropping;
- the first, final, and every intermediate fitted level in prediction,
  reconstruction, EDF accounting, and curve reporting;
- unseen FS/SZ group prediction returning the population curve only when
  `unseen="population"`, while ordinary fixed categoricals remain strict;
- canonical equality of numeric group labels `0.0` and `-0.0`;
- duplicate group geometry rejected before penalty-component construction;
- stable penalty-component identities rather than positional cursor inference;
- low-cardinality numeric marginals failing with a specific instruction to
  reduce `k` or choose a suitable non-smooth feature, rather than an obscure
  linear-algebra failure;
- very large smoothing parameters converging to SZ's unpenalized null space,
  not incorrectly collapsing the deviation to zero;
- fit/predict parity for a global spline plus SZ without an undocumented
  overlap-residualization transform;
- summaries retaining every co-fitted smooth even when a factor-smooth term
  has sparse or unusual fitted levels.

## Testing and Acceptance Evidence

Implementation follows test-driven development. Required evidence is:

### API and validation

- Constructor defaults prove existing FS calls are unchanged.
- FS/SZ names, component policies, cloning, and reconstruction are covered.
- SZ requires an explicit resolved `Spline(variable)`.
- Explicit `Categorical(group)` and `RandomEffect(group)` conflicts fail.
- Duplicate `(variable, group)` factor smooths fail even with custom names.
- FS standalone and FS plus global spline continue to fit.
- `splines=None` is silent; every non-`None` `splines` value emits exactly one
  `FutureWarning` containing the explicit-feature migration spelling.
- Deprecated shorthand behavior is otherwise retained during the compatibility
  window.
- Internal cross-validation, profiling, cloning, and deserialization do not
  multiply the warning after the user's original construction.

### Matrix algebra

- Materialized SZ design equals `(factor contrast) x marginal basis`.
- Penalty equals `(C'C) kron S`; rank and pseudo-log-determinant match dense
  eigendecomposition.
- Exact and discrete `matvec`, `rmatvec`, Gram, dense cross, and fused moments
  match dense oracles.
- Sum of reconstructed level curves is zero on training and prediction grids.
- Tests forbid `toarray()` and full-Hessian construction on structured paths.

### Solver and REML

- Randomized constrained structured solves, log determinants, selected
  covariance, traces, and derivatives match dense free-coordinate oracles.
- Cases cover no ordinary columns, ordinary columns, Gaussian and Poisson
  PIRLS, fixed lambda, estimated lambda, and `discrete=True`.
- Thin singular local blocks succeed when the global constrained model is
  identifiable; genuinely unidentified cases fail with the specified error.
- Finite-difference REML gradient/Hessian checks cover the SZ component.
- Existing RE/FS structured and dense parity suites remain green unchanged.

### mgcv parity

Pinned fixtures identify R 4.5.3, mgcv 1.9-4, and the exact fixture generator.
The shared-SZ reference uses:

```r
s(x, f, bs="sz", k=6, xt=list(bs="ps"), m=2, id=1)
```

Gaussian `gam`, Poisson `gam`, and Poisson `bam(discrete=TRUE)` cases compare
design/penalty invariants, predictions, deviance, EDF, curve effects, and
smoothing parameters after documented scale conversion.

Construction-level assertions pin the directly observed mgcv 1.9-4 contract:
with four levels and `k=6`, the SZ design has 18 columns, one penalty under
`id=1`, penalty rank 12, nullity 6, exactly zero summed prediction-design rows
over levels, and a finite `1 x 18` one-row `PredictMat`. A companion reference
without `id=1` proves that mgcv assigns a separate smoothing parameter per
level, while SuperGLM's initial shared-lambda behavior matches the `id=1`
case.

### Performance

- A large-`K` exact and discrete benchmark proves the structured backend is

- cProfile output identifies the actual fit call stack and top cumulative

- The benchmark confirms no expanded `n x (K-1)k` matrix or
  `(K-1)k x (K-1)k` Hessian.
- SZ structured fitting must beat the dense reference beyond the documented
