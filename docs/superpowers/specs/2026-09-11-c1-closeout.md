# C1 closeout specification

The user requires a finite checklist, implementation and review with at most
two subagents. This specification freezes the acceptance requirements already
recorded in the roadmap and discrete-performance plan. It does not add a new
solver, family, grouping scheme or numerical certification requirement.

## Fixed scope

The capacity fixture is the existing mostly-distinct, two-predictor Gaussian
model, at fixed coefficient width. The public Gamma book remains a numerical
control. Existing eager APIs and other family routes remain supported.
The stored model, knots, centering, supports, penalties, weight semantics,
rank decisions, convergence rules, inference and source-mutation checks are
preserved. Observation work remains linear in row count.

The latency fixture remains N=1,048,576, q=102, four knots and 256 bins.
Compilation, optimization and finalization remain inside its public fit clock.

## Numbered acceptance checklist

1. [x] **Existing foundation.** Public observed chunking, signed global moments,
   bounded derivative replay, immutable child caching and compact obsolete
   history are implemented. The 15-second milestone and initial N/q diagnostic
   have evidence. Keep their regression coverage; do not repeat those audits.
2. [ ] **Replayable inputs and one compiled model.** The bounded route must not
   require resident full-row training frames, response, weights, offsets or
   row-design buffers. Compile transformations once, then replay bounded rows.
   Account for input storage and preprocessing separately from solver RAM.
3. [ ] **Bounded likelihood preparation.** Root preparation and validation use
   bounded owned chunks; canonical model identity and live source authority
   survive. Children remain owned, cached within the existing 64 MiB allowance,
   and invalidated when their source changes. Gaussian carrier removal is one
   concrete substep, not completion of this item.
4. [ ] **Bounded initialization and null fit.** Neither stage implicitly owns
   full-row parameter, target, residual or derivative arrays in bounded mode.
   Preserve the existing initialization equations, offsets and null likelihood.
5. [ ] **Bounded live endpoints and outputs.** Current, plateau and final states
   use explicit streamed or backed row access in bounded mode. Existing eager
   output access stays available through deliberate materialization. Preserve
   practical/strict stops, covariance, diagnostics and artifact validation.
6. [ ] **Numerical and capacity acceptance.** Compare the same stored model at
   tractable N first, then complete the 10-million- and 100-million-row Gaussian
   fits in that order. Record outputs or streamed reductions, convergence,
   wall/CPU, fit peak RAM, backend, row passes and storage traffic. Separate
   fixture/preparation/output clocks. Run the Gamma control. A smaller passing
   fit never checks off a larger one.
7. [ ] **Latency acceptance.** Demonstrate the 12.5-second target on the unchanged
   million-row fixture with three fresh confirmations and fair dense controls.
   Report every valid sample, median/range and separate dispatch/profile
   evidence. A memory reduction does not check off this item.

Full C1 sign-off requires every box above. Implementation, measured capacity and
measured latency are separate statuses; a blocked measurement stays unchecked.

## Bounded-row interface decision

1. The new public route prepares a persistent `PreparedLSSData` directory from
   an iterator of bounded column batches. `SuperLSS.prepare_rows(batches, path,
   *, response, sample_weight=None, weight_semantics="prior", offsets=None,
   block_rows=65536)` names response, weight and offset columns explicitly;
   `offsets` maps predictor names to column names. Preparation stores typed rows
   and learns one compiled model across the complete source. It must preserve
   the existing global knots, centering, category dictionaries and penalties;
   a separate compilation for each block is forbidden. Its source generation
   and compiled-model identifier bind `PreparedLSSData` to both inputs. Later
   fits reuse those files instead of repeating preparation.
2. `SuperLSS.fit_prepared(data, *, lambdas=None, solver_config=None)` performs
   fixed-smoothing fitting. `lambdas` has the existing `Mapping[str, float]`
   contract. `fit_reml_prepared(data, *, lambdas=None, solver_config=None,
   efs_config=None, retain_history_rows=False)` preserves the existing REML
   initialization and history choices. Both return `self`, as the eager APIs
   do. Initial admission is exact `GaussianLS`, its default links and two
   predictors, complete observations, prior/frequency weights, and the existing
   admitted numeric, categorical, discretized SSP and spline-by-category
   groups at the existing coefficient-dimension limits. Other ordinary routes
   keep their behavior. The prepared route rejects unsupported admission
   explicitly rather than silently allocating an eager dataset.
3. A private `PreparedRowStore` supplies verified owned blocks to the compiler,
   likelihood preparation, initialization, null fitting and solver. It exposes
   row counts, a typed schema and generation identity, never an ndarray or a
   whole-dataset mapping. A prepared-likelihood descriptor holds that source
   and the existing family/weight/observation metadata; each verified block
   produces an ordinary owned child likelihood plan. The existing global
   moment accumulation consumes its compiled child design/execution plan.
   Root descriptors do not pretend to satisfy full-array weight contracts.
4. Source authority is content-based. Each read verifies the pinned manifest,
   index and touched block bytes; read-only flags and timestamps confer no
   authority. The existing child cache keeps its 64 MiB budget. A cache hit
   first verifies the corresponding source range, then checks the unchanged
   family, link, compiled-model and child authority. Every complete pass binds
   its certificate to the same generation and verified block contents. This
   costs fresh reads and hashing on hits, which must appear in traffic/pass
   evidence. Returned immutable bytes represent the verified snapshot; later
   file mutation cannot change them and is rejected on subsequent access.
5. The same blocks feed initialization and null reductions. Accepted, plateau
   and final endpoints use explicit owned row-file handles. The existing
   terminal prediction pass writes those files; endpoint comparisons and LAML
   derivative work replay bounded rows without rebuilding an N-row stencil or
   leverage array. `fitted_rows.iter_batches()` exposes backed output;
   `materialize_rows()` deliberately creates eager output. Prepared fitting
   must not implicitly populate eager `eta`/`theta` fields. Directory save/load
   validates and streams backed rows; existing eager serialization remains.
   Prepared inputs and compiled files persist across fits. Only transient
   endpoint files have cleanup tied to result/history ownership.

### Packet 2 storage and verification contract

Packet 2 implements this complete private storage interface. It adds no public
fit methods, compiler, likelihood adapter, optimizer or endpoint implementation.
All names below live in `superglm.distributional.row_store`.

```python
RowColumn(name: str, dtype: str)  # frozen; ordered column schema
RowRangeAuthority(generation: str, start: int, stop: int,
                  block_hashes: tuple[tuple[int, bytes], ...])  # frozen
VerifiedRowBlock(start: int, stop: int, columns: Mapping[str, np.ndarray],
                 authority: RowRangeAuthority)  # frozen; immutable mapping

RowStoreWriter(path: Path, schema: tuple[RowColumn, ...], *,
               metadata: Mapping[str, JSONValue] | None = None,
               block_rows: int = 65536)
RowStoreWriter.append(columns: Mapping[str, np.ndarray]) -> None
RowStoreWriter.finish() -> PreparedRowStore
RowStoreWriter.abort() -> None

PreparedRowStore.open(path: Path, *,
                      expected_generation: str | None = None) -> PreparedRowStore
PreparedRowStore.validate_generation() -> None
PreparedRowStore.read_verified(start: int, stop: int) -> VerifiedRowBlock
PreparedRowStore.verify_range(start: int, stop: int) -> RowRangeAuthority
PreparedRowStore.iter_verified(*, start: int = 0, stop: int | None = None,
                              batch_rows: int | None = None) -> Iterator[VerifiedRowBlock]
```

`JSONValue` means null, boolean, integer, finite float, string, list of these
values or a dictionary with string keys. The store exposes immutable `schema`
and `metadata`, plus `n_rows`, effective `block_rows`, `generation` and
`retained_index_bytes`. The metadata is for explicit column bindings and
category dictionaries; it cannot contain executable or pickled objects.

1. Admit 1–128 unique nonempty column names and only canonical little-endian
   `"<f8"`, `"<i8"`, `"<i4"` and `"|u1"` one-dimensional arrays of equal
   length. Append accepts exact ndarrays, checks dtype without coercion, and
   copies their bytes. It does not call `__array__`, infer object dtypes, or
   apply family validation or zero-weight filtering. Preserve numeric bits,
   including nonfinite values, for the existing family boundary to validate.
   Category labels belong in bounded JSON metadata; row columns contain codes.
2. Limit a block payload to **8 MiB**, the complete binary index to **1 MiB**,
   and the UTF-8 manifest to **64 KiB**. Limit admitted rows to **100,000,000**.
   Requested `block_rows` is an integer in `[1, 65536]`; the effective value is
   `min(requested, (8 * 2**20) // sum(dtype.itemsize for dtype in schema))`.
   All blocks except the last have that length. Refuse an append before its
   resulting row/block count would exceed the row or index limit. Small block
   choices may therefore admit fewer than 100 million rows. At the default
   request, even 128 float64 columns admit the 100-million-row target.
3. Write uncompressed column-major payloads to deterministic
   `blocks/{ordinal:08d}.bin` files. Each index record is exactly
   `struct.Struct("<QQQ32s")`: start, stop, payload byte count, SHA256 digest.
   Validate contiguous coverage, block lengths and exact byte counts with
   checked Python-integer arithmetic. The manifest records the format tag
   `superglm-row-store/v1`, schema, metadata, row/block counts, effective block
   length and index SHA256. Encode canonical sorted-key JSON with compact
   separators, UTF-8 and `allow_nan=False`; reject duplicate JSON keys.
   Generation is SHA256 of `b"SuperGLM/row-store/v1\0" + manifest_bytes +
   index_bytes`. It identifies content, so unchanged files remain reusable.
4. Pin immutable manifest/index bytes at open. Check lengths before allocation,
   require regular files and exact lengths, and reject symlinks and unsupported
   formats. Do not expand the index into an N-entry Python-object collection;
   decode fixed records on demand. Each read or verification checks manifest
   and index against the pinned generation before and after block I/O. Hash
   the complete touched payloads against pinned records, including unaligned
   ranges. `validate_generation` checks manifest/index only; it does not claim
   to verify unread payloads. `verify_range` performs the same payload checks
   as `read_verified`, without assembling returned columns. Later cache hits
   must use it even when cached children have valid immutable backing.
5. Ranges are nonempty integer half-open intervals within `[0, n_rows]`, with
   length at most effective `block_rows`; booleans are not indices. A range can
   touch at most two stored blocks. Iteration uses that same limit and retains
   no previously yielded block. Returned columns have independent owned
   immutable `bytes` backing, with no writable owner, file mapping or parent
   store reference; the mapping cannot be modified. Do not cache payloads in
   the store. Keeping a returned block alive must not keep the store alive.
6. Account for pinned metadata bytes, bounded fresh metadata buffers, one
   loaded payload and output assembly/conversion separately. Across one read,
   byte-buffer ownership is at most `3 * 8 MiB + 2 * (1 MiB + 64 KiB)`, excluding
   blocks deliberately retained by the caller and small schema/control
   objects. Actual metadata traffic is twice the manifest-plus-index length
   per call; payload traffic is the sum of complete touched block lengths,
   at most 16 MiB. Verification on cache hits has the same read traffic.
   Report these counts rather than claiming zero-I/O caching. Sequential
   consumers use effective block boundaries to avoid repeated payload reads.
7. Publish into a newly created directory; refuse an existing destination.
   Write blocks and index before atomically installing the completed manifest.
   An incomplete directory cannot open as a store. `abort` removes only the
   writer's unpublished work. Closing or collecting a published store never
   deletes it. Reopening with `expected_generation` must reject a replacement
   generation. Invalid caller arguments raise `TypeError`/`ValueError`;
   corruption or generation mismatch raises `RowStoreIntegrityError`, a
   `ValueError` subclass, before returning data or authorizing a cached child.

### Packet 3 compiled-source contract

Packet 3 connects preparation to the existing feature compiler and group
execution. Its public product is `SuperLSS.prepare_rows(...) -> PreparedLSSData`
with the signature above. It learns one model from the entire retained source,
writes reusable compiled rows, and provides working bounded predictor replay.
Fixed/REML fitting, root likelihood provenance, null fitting and endpoints are
separate consumers. Their absence must not be hidden behind an eager fit call.

1. Add `PreparedLSSData` in `distributional/prepared_rows.py`, exported from the
   package alongside `SuperLSS`. It exposes `n_rows`, `block_rows`,
   `coefficient_names`, `term_slices`, `penalty_names`, `model_identifier` and
   `generation`. These contain no N-row arrays. Its executable interfaces are:

   ```python
   PreparedLSSData.open(path: Path, *, expected_generation: str | None = None) -> PreparedLSSData
   PreparedLSSData.read_verified(start: int, stop: int) -> CompiledRowBlock
   PreparedLSSData.iter_verified(*, batch_rows: int | None = None) -> Iterator[CompiledRowBlock]
   PreparedLSSData.predict_eta(coefficients: np.ndarray, *,
                               batch_rows: int | None = None) -> Iterator[tuple[int, int, np.ndarray]]
   ```

   `CompiledRowBlock` is frozen and contains `start`, `stop`, immutable owned
   `response`, `weight_values`, `input_positions`, a tuple of owned offset
   arrays, a tuple of ordinary `PredictorExecutionPlan` children, and the tuple
   of `RowRangeAuthority` values covering its row stores. Prediction validates
   a finite coefficient vector in the published coordinate order, uses those
   child group matrices and offsets, and yields immutable `(rows, 2)` blocks.
   Reopening and repeating prediction must use stored geometry without learning
   features again. There is no array conversion or eager prediction property.
2. The public adapter consumes the caller's batch iterator once. Normalize
   bounded batches into typed Packet 2 storage; explicit categorical specs
   retain bounded label dictionaries and numeric code columns. Preserve declared
   levels, base selection, zero-weight exclusion, positional order and the
   prior/frequency distinction. Preparation owns label encoding: preserve label
   values/types and the eager global level ordering, then remap temporary ingest
   codes to that frozen ordering before publishing compiled codes. Do not
   stringify labels or let batch-local category orders define the model.
   Validate weights before validating retained
   response/features, as the eager boundary does. An all-zero batch may be
   skipped; an all-zero dataset is an error. Record original/retained counts
   and store retained input positions. Do not create a full-row mask or position
   vector. The source spool remains available for preparation replay and later
   provenance derivation; it is never retained as a frame.
3. Add `_prepared_predictor_compiler.py` for family-neutral bounded learning
   helpers. Clone feature specifications once. The distributional entry point
   in `prepared_rows.py` is
   `compile_prepared_predictors(source, *, predictors, parameters,
   weight_contract, offsets, n_bins_config, lambda2, path) -> PreparedLSSData`;
   `source` is the Packet 2 store and offsets are predictor-to-column bindings.
   The distributional adapter supplies link/offset metadata; family-neutral
   learning helpers consume explicit geometry/likelihood mass and feature
   configuration, and do not import a family or optimizer. The public adapter
   supplies the same compiler configuration as the eager discrete route.
4. Resolve global spline boundaries, interior knots and discretization support
   before emitting any compiled row. For nonconstant continuous columns, spool
   sorted runs in bounded buffers and merge one feature at a time. Preserve
   unique-value quantiles, row/frequency quantiles, explicit boundaries and
   knots, the existing duplicate-knot fallback, and the existing discretization
   bin rule. Select the exact required order statistics from sorted support;
   never substitute a sketch, sample or per-batch quantile. Aggregate physical
   counts and frequency mass separately. Use at most 64 MiB of sort/merge byte
   buffers, fixed fan-in merges, and bounded run-index buffers. Count run writes,
   merge reads and every source pass as preparation work. Release scratch at
   explicit preparation completion/abort; published source files persist.
5. Replay retained rows to accumulate the existing sufficient quantities:
   categorical geometry mass, spline identifiability constraints on the actual
   raw values, support likelihood mass for SSP transforms, selected-smooth
   centering mass, and per-category support mass for spline-by-category terms.
   Factor these quantities through the same penalty, projection and SSP
   routines used by the eager compiler. Keep likelihood mass separate from
   geometry mass. Extract small shared helpers where their current entry
   points require full-row arrays; do not invoke `build` once per block or feed
   synthetic rows to learn replacement geometry. Preserve term order, names,
   group widths, penalty policies and rank/refusal rules. Floating reductions
   use dimension/epsilon/absolute-term bounds; discrete choices must agree.
6. Freeze coefficient/support metadata and emit typed compiled rows once.
   Store response, likelihood weight, retained input position and offsets in
   one row store, plus one row store per predictor. Numeric groups store their
   numeric columns; categorical groups store codes; SSP groups store bin codes;
   spline-by-category groups store bin and activity codes. Keep `B_unique`,
   `R_inv`, projections and local penalty components in bounded metadata, not
   repeated row columns. Reconstruct exact built-in group types for each read.
   The effective read size is the minimum block limit of the component stores.
   Refuse configurations exceeding Packet 2 schema/index limits or the existing
   global-moment group/support/coefficient limits before publishing.
7. The compiled manifest lists component generations and the ordered predictor,
   group, link, coefficient and penalty metadata. Store numeric metadata as
   typed raw arrays with declared shapes, byte counts and digests; decode only
   the admitted built-in descriptor kinds. No pickle, object array, arbitrary
   import or executable feature object is loaded. Bound compiled metadata
   payloads to the existing 64 MiB preparation allowance and include their
   bytes in ownership accounting. The model identifier hashes canonical
   coefficient/support metadata; the prepared generation also binds every
   row-store generation. Publish the manifest last. Opening and each read
   verify metadata and all component stores used for that range. Owned compiled
   rows are the fit source; their immutable snapshot does not alias the caller's
   original batches or a temporary eager model. Corruption refuses replay.
8. Packet 3 does not construct a fake `ResolvedLikelihoodWeights` root. The
   later likelihood consumer must stream canonical root digests and adapt the
   full `dropped_input_positions` reporting owner explicitly. It can obtain
   verified weight values and retained positions from `CompiledRowBlock` and
   revisit the persistent source spool. Likewise, a later global-moment builder
   must accept coefficient/support descriptors without inventing N-row groups.
   Packet 3's required connected consumer is the actual existing group execution
   used by `predict_eta`, exercised after reopening the compiled source.

## Execution boundaries

One implementer owns the current packet. One reviewer checks its numbered
requirements and introduced defects. Root coordinates integration and serial
measurements. No third agent, duplicate broad audit or new benchmark sweep.
Use existing failing fixtures and measurements where they apply. A packet ends
with its focused regressions, source review and relevant complete-fit evidence.

The first packet is the already-reviewed Gaussian prepared-carrier change in
six production files. It has its own exact implementation plan and checked
substeps. Subsequent packets must address items 2, 4 and 5 through the same
bounded row path; isolated allocation reductions cannot substitute for them.
Details may be refined to fit existing interfaces, but the seven acceptance
items and numerical contracts above are fixed.

The roadmap has inconsistent wording about automatic threading. The finite
N/q diagnostic is complete and later text defers a general policy. C1 therefore
uses explicit, recorded thread settings and fair controls; a universal automatic
policy is not an extra closeout requirement. Billion-row fits, new families or
parameter counts, exact joint-row grouping, categorical support experiments and
exhaustive memoization are also outside this checklist.
