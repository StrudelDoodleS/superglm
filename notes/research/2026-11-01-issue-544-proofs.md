# Issue 544 stage 2: what the Lean proofs establish

Date: 2026-11-01. Repository base: `ff2ed52d` (branch `claude/issue-544-gamma-bounds`).

This note covers five Lean files in
[lean-gaussian-certificate/](lean-gaussian-certificate/), which share the pinned Mathlib
with the earlier proofs ([README](lean-gaussian-certificate/README.md),
[interaction-operator proof](2026-09-13-interaction-operator-proof.md)). They prove facts
about the real-valued formulas behind this PR's analytic derivatives. They do not prove
anything about floating-point evaluation: that accuracy is measured against mpmath in the
test suite. Each theorem's docstring names the code function and formula it certifies.

Every main theorem depends only on Lean's standard axioms `propext`, `Classical.choice` and
`Quot.sound` (`#print axioms` at the end of each file). There is no `sorry`, no new axiom
and no `native_decide`. The exact-rational computations use `decide +kernel`, so Lean's
kernel evaluates them and the axiom `Lean.ofReduceBool` is not involved.

## 1. The window combiner

With `phi(Δ) = log(-expm1(Δ))` and `kappa = 1/expm1(-Δ)`, for every real `Δ < 0`:

| Theorem | Statement |
|---|---|
| `hasDerivAt_phi` | `phi' = -kappa` |
| `hasDerivAt_kappa` | `kappa' = kappa (1 + kappa)`, for every `Δ ≠ 0` |
| `phi_deriv_two` | `phi'' = -kappa (1 + kappa)` |
| `phi_deriv_three` | `phi''' = phi'' (1 + 2 kappa)` |
| `phi_deriv_four` | `phi'''' = phi'' (1 + 6 kappa (1 + kappa))` |
| `kappa_pos` | `kappa > 0`, so every factor in `_window_log_derivatives` is a sum of positive terms |
| `log_window` | `log(T_near - T_far) = log T_near + phi(log T_far - log T_near)` for every `0 < T_far < T_near` |
| `delta_neg` | that `Δ` is negative |
| `phi_tendsto_atBot` | `phi(Δ) → 0` as `Δ → -∞`: an absent far end (`T_far = 0`) leaves the near tail |
| `neg_phi_le_kappa` | `0 <= -phi <= kappa`: when `kappa` rounds to zero, so does the value correction |

The derivative statements use Mathlib's `iteratedDeriv`, so they state the derivatives
of the function `phi` itself. A polynomial identity that merely matched the code would not
establish that. The four polynomials agree exactly with the code's `derivatives[1..4]`.

The case `T_far = 0` is handled through the limit and not substituted into `log_window`,
because Lean's `log 0 = 0` convention would make that substitution meaningless.

**Not proved here:** composing `phi^(m)` with `Δ`'s jets. That is the multivariate
set-partition chain rule (`compose_derivatives`; Constantine and Savits 1996). The S1
oracle measures it.

## 2. The generalized gamma's uniform variable through `q = 0`

With `t = q w`, `lambda = e^t`, `g(t) = 2 (e^t - 1 - t)/t^2` and `g(0) = 1`:

| Theorem | Statement |
|---|---|
| `g_analyticAt`, `g_contDiff` | `g` is real analytic at every real `t`, hence `C^n` for every `n` |
| `g_pos` | `g(t) > 0` for every real `t` |
| `g_identity`, `lambda_identity` | `lambda - 1 - log lambda = (q w)^2 g(q w)/2` for all real `w, q` |
| `G_analyticAt`, `G_pos`, `G_zero` | `G = sqrt g` is analytic and positive, `G(0) = 1` |
| `zeta_analyticAt`, `zeta_contDiff` | `zeta(w, q) = w G(q w)` is jointly real analytic in `(w, q)`, through `q = 0` |
| `zeta_q_zero` | `zeta(w, 0) = w` |
| `eta_sq` | `eta = q zeta` satisfies `eta^2/2 = lambda - 1 - log lambda` |
| `sign_eta` | `sign eta = sign(lambda - 1)` |
| `eta_eq_temme` | `eta(w, q)` is Temme's variable `sign(lambda - 1) sqrt(2 (lambda - 1 - log lambda))` (DLMF 8.12.1) of `lambda = exp(q w)` |
| `zeta_eq_temme_div` | for `q ≠ 0`, `zeta = eta_Temme/q`, so `zeta` is the analytic extension of `eta/q` through `q = 0` |

Analyticity at `t = 0` comes from Mathlib's power series of `exp`. Taking the divided
slope (`dslope`) twice gives a function with power series `fslope (fslope expSeries)`, and
`g` is twice that function everywhere. Its value at 0 is the series coefficient `1/2!`,
which proves `g(0) = 1` instead of assuming it. Away from 0, `g` is a quotient of analytic
functions with a nonzero denominator. This removes the apparent singularity of `eta/q` at
`q = 0`. We found no published source that states this for the generalized gamma.

**Not proved here:** Temme's expansion itself, `F = Phi(zeta) - q phi(zeta) S` (Temme
1979; Gil, Segura and Temme 2012), the role of `S` and its truncation error, and the claim
`dF/dq = phi(w)(w^2 + 2)/6` at `q = 0`. S4 measures all of these against mpmath.

## 3. The coefficients `d_n` and `G_n`

Writing `t = log lambda` gives `eta = t G(t)` and `eta/(lambda - 1) = t G(t)/(e^t - 1)`.
The series `D(eta) = sum d_n eta^n` and `G(t) = sum G_n t^n` are therefore characterised
by two identities of power series in `t`:

1. `G(t)^2 = g(t) = sum_k 2 t^k/(k + 2)!`, with `G_0 = 1 > 0`;
2. `D(t G(t)) · (e^t - 1)/t = G(t)`.

`TemmeCoefficients.lean` contains `GTab` (`G_0..G_36`) and `dTab` (`d_0..d_36`) as exact
rationals. It checks both identities through `t^36` by kernel evaluation:

| Theorem | Statement |
|---|---|
| `G_sq_eq_g` | `sum_{i<=k} G_i G_{k-i} = 2/(k+2)!` for every `k <= 36` |
| `d_certificate` | coefficients 0-36 of `D(t G) · (e^t - 1)/t` equal `G`'s, computed in `ℚ[t]/(t^37)` |
| `coef_mulT` | the truncated product used is the Cauchy product, proved for all inputs |
| `compT_cons` | composition is Horner's rule |
| `dTab_two`, `dTab_low` | `d_2 = +1/12`; `d_0..d_4 = 1, -1/3, 1/12, -2/135, 1/864` |
| `low_orders_forced` | any `G_0 > 0, G_1, G_2, d_0, d_1, d_2` satisfying both identities through `t^2` must equal `(1, 1/6, 1/36)` and `(1, -1/3, 1/12)` |

`low_orders_forced` settles the sign question directly. The `d_2 = -1/12` printed in
Gil, Segura and Temme's arXiv v1 (eq. 2.37) satisfies neither identity. This confirms
S4's finding by a third, independent route.

All 37 `d_n` are proved. The `G` table goes to 37 entries; the engine stores 29.

Mutation checks were run on scratch copies and not committed. Setting `d_2 = -1/12`
makes `d_certificate` fail. So does adding 1 to the numerator of `d_36`, so the check
covers the table's last entry.

Lean does not see float64. The link to the engine's stored floats was checked outside
Lean, once. For 37 of 37 `_D` literals and 29 of 29 `_G` literals, Python's correctly
rounded `float(Fraction)` of the Lean table's rational equals the stored literal. The
rationals were generated independently of S4's Lagrange-Buermann routine, by the
square-root recurrence and forward substitution. The check reads the engine source with
`ast`, so numba is not imported:

```python
# python3 -I compare.py src/superglm/distributional/kernels/_gg_uniform_tail.py
import ast, sys
from fractions import Fraction as F
from math import factorial
N = 37
g = [F(2, factorial(k + 2)) for k in range(N)]
G = [F(1)] + [F(0)] * (N - 1)
for n in range(1, N):
    G[n] = (g[n] - sum(G[i] * G[n - i] for i in range(1, n))) / 2
U = [F(1, factorial(k + 1)) for k in range(N)]
E = [F(0)] + G[:-1]
mul = lambda a, b: [sum(a[i] * b[k - i] for i in range(k + 1)) for k in range(N)]
cols, p = [], [F(1)] + [F(0)] * (N - 1)
for j in range(N):
    cols.append(mul(p, U)); p = mul(p, E)
d = []
for k in range(N):
    d.append(G[k] - sum(d[j] * cols[j][k] for j in range(k)))
tables = {n.targets[0].id: ast.literal_eval(n.value.args[0])
          for n in ast.parse(open(sys.argv[1]).read()).body
          if isinstance(n, ast.Assign) and getattr(n.targets[0], "id", "") in ("_D", "_G")}
assert tables["_D"] == [float(x) for x in d]
assert tables["_G"] == [float(x) for x in G[:29]]
```

**Not proved here:**

- That a formal power-series identity determines the Taylor series of the real-analytic
  function. This is the standard composition theorem for convergent series (and
  Lagrange-Buermann, DLMF 8.12), assumed here.
- Uniqueness beyond order 2. Both identities are triangular in the unknown coefficients:
  the coefficient of `t^k` is `2 G_0 G_k + (lower terms)` in the first and
  `d_k + (lower terms)` in the second. So they determine every coefficient. Only orders
  0-2 are machine-checked to be forced.

## 4. The severity primitives

`softplus(z) = log(1 + e^z)`, `expit(z) = 1/(1 + e^-z)`, `log1mexp(t) = log(1 - e^-t)`,
`invexpm1(t) = 1/(e^t - 1)` and `gdev(y, m) = y/m - 1 - log(y/m)`:

| Theorem | Statement (domain) |
|---|---|
| `hasDerivAt_softplus` | `softplus' = expit` (all `z`) |
| `hasDerivAt_expit` | `expit' = expit(z) expit(-z)` (all `z`) |
| `hasDerivAt_log1mexp` | `log1mexp' = invexpm1` (`t > 0`) |
| `hasDerivAt_invexpm1` | `invexpm1' = -r (1 + r)` (`t ≠ 0`) |
| `hasDerivAt_gdev_y`, `hasDerivAt_gdev_m` | `∂gdev/∂y = (y - m)/(y m)`, `∂gdev/∂m = (m - y)/m^2` (`y, m > 0`) |
| `softplus_branch`, `expit_branch`, `invexpm1_branch`, `gdev_log_branch` | each numba branch evaluates the same real function |
| `gdev_window` | `|v| < 1/3` exactly when `1/2 < y/m < 2`, with `v = (m - y)/(m + y)` (the code comment) |
| `gdev_loader_series` | `gdev = (m - y) v/m + sum_{j>=1} 2 v^(2j+1)/(2j+1)` (`y, m > 0`; Loader 2000) |
| `gdev_direct_bound` | outside `(1/2, 2)`, `|y/m - 1| <= 3.3 gdev` (the docstring's claim, proved with Mathlib's nine-digit bounds on `log 2`) |

Mathlib (pinned rev) defines only the complex digamma, `Complex.digamma = logDeriv Gamma`.
It has no real digamma or polygamma. Here `psi = Gamma'/Gamma` on the positive reals,
with `psires(n, a) = psi^(n)(a) - d^n log(a)/da^n` and `sres(n, a) = a^(n+1) psires(n, a)`:

| Theorem | Statement (`a > 0`) |
|---|---|
| `Gamma_analyticAt`, `psi_analyticOnNhd` | `Gamma` and `psi` are real analytic on `(0, ∞)` (from complex differentiability on `Re s > 0`) |
| `psi_eq_digamma` | `psi(a) = Re Complex.digamma(a)` |
| `hasDerivAt_log_Gamma` | `(log Gamma)' = psi` |
| `hasDerivAt_gnorm`, `hasDerivAt_gnorm_sres` | `gnorm' = -psires(0, a) = -sres(0, a)/a` (the generator's `gnorm.fdiff`) |
| `hasDerivAt_psires` | `psires(n)' = psires(n + 1)` for every `n` |
| `hasDerivAt_sres` | `sres(n)' = ((n + 1) sres(n) + sres(n + 1))/a` for every `n` |
| `iteratedDeriv_log_succ`, `psires_0123_log_terms` | `d^(n+1) log a = (-1)^n n! a^(-1-n)`: the terms `psires_0123` subtracts (`1/a`, `-1/a^2`, `2/a^3`) and the generator's mpmath reference |
| `psi_add_one` | `psi(x + 1) = psi(x) + 1/x` |
| `iteratedDeriv_psi_shift` | `psi^(n)(x + 1) = psi^(n)(x) + (-1)^n n! x^(-1-n)` for every `n`: the four `shifted_*` updates of `polygamma_0123` |

**Missing from Mathlib, so not proved:**

- Stirling's series for `log Gamma` with Bernoulli coefficients and a remainder (DLMF
  5.11.1), used by `gnorm` for `a >= 10`.
- The asymptotic series for `psi` and its derivatives (DLMF 5.11.2 and 5.15.8,
  differentiated), used by `psires_0123`, `sres_0123` and `polygamma_0123`.
- The series about the origin, `psi(a) = -1/a - gamma + sum_k (-1)^k zeta(k) a^(k-1)`,
  used by `sres_0123` below `a = 1/4`.

These need either a real polygamma API or the Bernoulli-remainder form of Stirling's
formula. Mathlib has only the leading-order Stirling limit.

## 5. The node mixture (optional target)

For a finite node set with weights `ω_i > 0` and node log densities `l_i(θ)`, four times
differentiable on `ℝ`, `F(θ) = log sum_i ω_i exp(l_i(θ))`. With `p_i ∝ ω_i e^(l_i)` and
`c^(k) = l^(k) - E_p[l^(k)]`:

| Theorem | Statement |
|---|---|
| `hasDerivAt_F` .. `hasDerivAt_F3`, `iteratedDeriv_four_F` | `F' .. F''''` are the moment-to-cumulant forms in `mu_k = Z_k/Z_0`, at every `θ` |
| `F1_cumulants` | `F' = E[l']` |
| `F2_cumulants` | `F'' = E[l''] + Var(l')` |
| `F3_cumulants` | `F''' = E[l'''] + 3 Cov(l'', l') + E[c'^3]` |
| `F4_cumulants` | `F'''' = E[l''''] + 4 Cov(l''', l') + 3 Var(l'') + 6 E[c'' c'^2] + (E[c'^4] - 3 E[c'^2]^2)` |

These are the diagonal of `quadrature_window_jets`' sum over set partitions of joint
cumulants. The partitions of four positions with two or more blocks are 4, 3, 6 and 1 of
shapes (3,1), (2,2), (2,1,1) and (1,1,1,1). The last term is the fourth cumulant that
`_node_cumulant` forms by subtracting the three pairings.

A mutation check that flips the pairing sign in `F4_cumulants` fails. That mutation is
the one S1 could detect only at window width `1e-3`: at width `1e-8` the pairing terms
fall below `u`.

**Not proved here:**

- The multivariate entries. They are the polarisation of these diagonal statements: a
  symmetric multilinear form is determined by its diagonal.
- Gauss-Legendre truncation.
- The narrow-window switch.

**Incomplete-gamma series, not attempted in Lean.** This is the other half of the optional
target: term-by-term differentiation in `a` of `x^a e^-x sum_n x^n/Gamma(a + n + 1)`. The
route would be Mathlib's `differentiableOn_tsum_of_summable_norm` on a complex disc around
real `a`. That needs a summable bound on `|x^(s+n)/Gamma(s+n+1)|` over the disc, from
`1/Gamma(s+n+1) = 1/((s+1)...(s+n) Gamma(s+1))` and a bound on the entire function
`1/Gamma` over the compact disc. The result is Weierstrass's theorem on locally uniform
limits, a low-risk classical fact. Its cost was not justified beside the node-mixture
identities, where the tests are measurably blind.

## What remains measured, not proved

- Floating-point accuracy of every kernel. The mpmath oracles in `tests/` measure it.
- Truncation errors:
  - the 35-term Temme series (`TERMS`) and the 29-term `G` series;
  - Loader's 17 terms;
  - the Stirling, asymptotic polygamma and zeta series;
  - the Mills-ratio continued-fraction depth;
  - three-point Gauss-Legendre.
- Temme's uniform expansion itself (Temme 1979; DLMF 8.12; Gil, Segura and Temme 2012).
- The incomplete-gamma engine (S3): series, Legendre continued fraction and their jets.
- SymPy's own chain and product rules, and the code it generates. The primitives' `fdiff`
  rules are proved here; SymPy's composition of them is not.
- The multivariate Faà di Bruno composition (`compose_derivatives`) and the polarisation
  from these univariate statements to packed multivariate jets.

## What the proofs contradicted

Nothing in the code. Every formula checked agrees with the code and its comments,
including two numerical claims in comments: the `|v| < 1/3` window and the
`|y/m - 1| <= 3.3 gdev` bound.

One discrepancy outside the repository. S4's handoff note summarises the variable as
"`eta = sign(q) sqrt(2(lambda - 1 - log lambda))`, `zeta = eta/|q|`". That formula has the
wrong sign whenever `w < 0`. The code and the module docstring use `zeta = w G(q w)` and
`eta = q zeta`, which `eta_eq_temme` and `zeta_eq_temme_div` show is Temme's `eta` with
`zeta = eta/q`. A search of `src/`, `tests/`, `tools/`, `docs/` and `notes/` found the
wrong form nowhere in the repository.

## Rebuild

From `notes/research/lean-gaussian-certificate/`, with the elan toolchain on `PATH`:

    lake exe cache get        # prebuilt Mathlib for the pinned rev; no source build
    lake build WindowCombiner GGChangeOfVariables TemmeCoefficients SeverityPrimitives NodeMixture

Build the targets one at a time on a shared machine, because each process importing
Mathlib holds 6-9 GB. A single file can be checked with `lake env lean File.lean`. Measured
on this machine, the check takes 7-9 s per file plus about 6 s to load Mathlib.
`TemmeCoefficients` takes 54 s (kernel evaluation of the two 37-term identities, 9.3 GB
peak). The full default `lake build`, all nine libraries, exits 0.

Environment: Lean 4.33.1 (commit `819816b2e0a3bf405af45ae5c7af2491d8f5bee6`), Lake
5.0.0-src+819816b, Mathlib `0df444a360eaa60ab8c11dca51a86af692955474`.
